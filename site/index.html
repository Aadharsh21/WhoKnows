Your teammate's asleep.Their agent isn't.

Everyone on the team gets their own AI agent. When you need something, your agent finds whoever knows about it, gets what that person's rules allow, and waits for their yes before touching their files or their time. Nobody gets woken up.

    Who needs this

    Any group where the person who knows is often busy or asleep.

    • Capstone and senior design

      Eight to twelve people, one demo day, and nobody remembers who wrote which part. That's the night in the player above.

    • Hackathon teams

      Thirty-six hours, and half the team is asleep at any given moment. "Who changed the API?" gets an answer without waking anyone.

    • Student orgs

      Officers graduate and take what they know with them. The backup check spots the parts only one person knows while there's still time to hand them over.

    • Research labs

      "Which script made figure 3?" gets answered from a grad student's own notes, with the file named, even at 2 AM.

    • Teams across time zones

      Online and international students work while their teammates sleep twelve hours away. The agent answers for the person who's asleep.

    • Course staff

      Who's grading question 3, where the rubric lives, and who can cover office hours, without a message to every TA.

    How the agents decide

    Each agent works for one person and answers only for them. These rules are in the code, not just in a prompt, so a confused or tricked agent still can't break them.

    Find who knows
    Nina's agent asks all nine agents at once. Each one checks its own person's work: the team plan, the repo's CODEOWNERS file, recent commits, and what the person said they're doing tonight. Two answer. The other seven just say no.
    Share by each person's rules
    Every file sits in one of three tiers, set by its owner.
    • Shared on its own: notes and docs.
    • Shared after a yes: drafts, code, anything not listed.
    • Never leaves: secrets and personal files. Other agents don't even learn they exist.
    A gate re-reads every outgoing file from disk and re-applies the owner's rules, so an agent that's been fooled still can't leak one.
    Answer with sources
    A question goes to the people who know. Each agent answers for its person, even one who's asleep, by quoting their shareable notes word for word and naming the file. The gate checks every quote against the file on disk, so an agent can't invent one or quote a draft. If nothing written down answers it, the question goes to the single best match, at a decent hour.
    No part rests on one person
    The agents also count who knows each part the demo depends on. When it's only one person, a teammate who is awake and watches that code is asked to be the backup, and their agent pulls the shareable notes right away. Tonight Ade backs up Nina on checkout and Lucas backs up Priya on login.
    Ask before acting
    An agent never offers its person's time and never changes their files without asking first. If they're asleep, the question waits for morning. In every run of the story, nobody's phone lights up while they sleep.
    Settle conflicts
    Two fixes for the same lines wait side by side and the owner picks. Three people who need the same person get one shared slot instead of three interruptions. Two people writing the README get a split. A part nobody owns gets a volunteer, starting with whoever is awake and good at it.
    Earn trust, keep receipts
    Anything an agent does without asking while its person sleeps goes on a receipt they see when they wake, with one tap to make it ask first next time. After an owner approves a small, clean change, their agent offers to let that teammate's small changes through without asking. Each one still sends a commit, and undo is one tap.
    Send changes like commits
    A change to someone's file is a request, drafted on the owner's side, shown as an exact before and after, and saved only after they approve. Then it goes out like a commit, but only to the people it affects: whoever asked, anyone with a copy, anyone who works on that code or watches it. Copies refresh themselves. Everyone else hears nothing.

        How it works and what it assumes

          Try it on a real repo

          The night above runs on a made-up team. This runs on a real one. Point WhoKnows at any git repository and every recent contributor gets an agent that knows only their own commits. Here it is on Flask, with 60 contributors' agents:

          $ python3 -m whoknows.repo flask "who knows the session cookie code?"

Asked 60 agents at once. 6 know, 54 said no. People notified: 0.

  value might result in browsers with several competing session cookies."

          It reads only what people already committed: file paths, commit messages and CODEOWNERS. Run it on your own team's repo with python3 -m whoknows.repo PATH "your question".

          When an agent goes rogue

          Theo's agent reads a poisoned README in some package and starts following its orders. It asks for Omar's secrets, tries to wipe one of his files while skipping his approval, and asks Nina's agent to forward Omar's notes. Then it tries to get other agents to send private files anyway. Every attempt stops, and Omar hears about all of it when he wakes up.

          Run it yourself

          The story above is a replay of a Python engine with no outside packages. Run any branch in a terminal:

          python3 -m whoknows
python3 -m whoknows --choose omar_fix=theo --choose theo_help=no
python3 -m whoknows --rogue
python3 -m whoknows.bench        # the numbers above

          The same agents also run live in Discord: each person DMs the bot, takes a seat, and talks to their own agent, while empty seats are played by simulated teammates. Every message between agents shows up in a #backchannel channel.

          83 tests cover the sharing tiers, the gate, quotes, colliding changes, commits, trust and undo, the team board and backups, every one of the 48 story branches, the rogue agent, the benchmark, and the live Discord layer. They run on Python 3.9 and 3.13 on every push. See the code on GitHub, or read the one-page design.
